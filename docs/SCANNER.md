# اسکنر بارکد/QR

## ۱. چرا روی بعضی گوشی‌ها (مثل Samsung A55) پیش‌نمایش زنده است ولی بارکد خوانده نمی‌شود

سه علت جدا، که هر سه با «دوربین روشن می‌شود ولی هیچ واکنشی نیست» جور درمی‌آیند:

1. **کپی فریم سیاه.** روی چند سامسونگ `createImageBitmap(video)` و گاهی
   `canvas.drawImage(video)` سایز درست برمی‌گرداند ولی پیکسل‌ها صفرند. پیش‌نمایش
   زنده می‌ماند چون Surface جداگانه کامپوزیت می‌شود. نسخهٔ بازنویسی فقط اگر
   `createImageBitmap` **throw** می‌کرد به canvas می‌رفت — بیت‌مپ سیاه throw نمی‌کند.
2. **حذف `BarcodeDetector` بومی.** WebView اندروید از Chromium ۸۳ این API را دارد
   (کروم، سامسونگ اینترنت، WebView سیستمی). `detect(video)` فریم را از خودِ
   پایپ‌لاین دوربین می‌خواند و به کپی canvas وابسته نیست. همان موتوری است که روی
   A55 کار می‌کند وقتی ZXing فریم سیاه می‌بیند.
3. **لنز ultra-wide.** `facingMode: "environment"` روی سامسونگ اغلب لنز ۰.۶× را
   باز می‌کند. استریم فریم می‌دهد پس قبلاً همان نگه داشته می‌شد و لنز اصلی
   هیچ‌وقت امتحان نمی‌شد. بارکد در کادر دیده می‌شود ولی تار/کوچک است.

## ۲. تصمیم‌های معماری

### دو موتور، بدون مسابقهٔ مسدودکننده

- **Native** (`BarcodeDetector.detect(video)`) آتش‌و‌فراموش، حداکثر یکی در پرواز.
  گرم‌شدن ML Kit تا ۴ ثانیه وقت دارد؛ بعد از دو آویزان شدن پیاپی خاموش می‌شود
  تا ZXing تنها بماند. نتیجهٔ دیررس دور ریخته نمی‌شود.
- **ZXing-wasm** در Worker (یا ترد اصلی اگر handshake در ۸ ثانیه نرسید).

هر کدام زودتر خواند برنده است؛ `accept.ts` تکرار را حذف می‌کند. نام فرمت بومی
(`ean_13`) به خروجی zxing (`EAN13`) نگاشته می‌شود تا EAN اشتباهاً تأیید دوم نخواهد.

### گرفتن فریم

```
canvas.drawImage(video) + getImageData     ← پیش‌فرض
  ↓ سه فریم یکنواخت/سیاه (واریانس نزدیک صفر)
ImageCapture.grabFrame() از خودِ تراک      ← وقتی کپی ویدیو سیاه است
```

`createImageBitmap(video, crop)` دیگر مسیر اصلی نیست.

کادر روی صفحه با `object-fit: cover` است؛ کراپ دیکود از همان ناحیهٔ دیده‌شده
محاسبه می‌شود نه از درصد خام `videoWidth`.

### انتخاب لنز عقب + تأیید زنده‌بودن

1. استریم کمینه برای گرفتن مجوز.
2. `enumerateDevices()` و امتیازدهی: ultra / tele / macro / depth تنزل رتبه.
3. استریم اولیه **فقط اگر کاندیدای اول** باشد نگه داشته می‌شود؛ وگرنه بسته
   می‌شود و لنز اصلی با `deviceId: { exact }` باز می‌شود.
4. فوکوس پیوسته و زوم شروع ۱.۶× جداگانه اعمال می‌شوند (نه یک `advanced` دسته‌ای).
5. دکمهٔ تغییر لنز برای کاربر باقی می‌ماند.

انتخاب لنز **ذخیره نمی‌شود**.

### فشار معکوس (backpressure)

حلقه با `requestVideoFrameCallback` (یا rAF) اجرا می‌شود و **هم‌زمان فقط یک دیکود
ZXing** در پرواز است. Native جدا و غیرمسدودکننده است. فریم جدید در صف نمی‌رود.

فریم‌های فرد کادر را کمی زوم دیجیتال می‌کنند (۰.۶۲) تا بارکد ریز هم خوانده شود.

### دروازهٔ دقت

`validateOptionalChecksum` روی `false` است (روشن بودنش CODE-39 بدون رقم کنترلی
اختیاری را رد می‌کرد). به جایش:


- **پذیرش فوری** برای فرمت‌هایی که خودشان کنترل می‌شوند: QR، DataMatrix،
  EAN-8/13، UPC-A/E، CODE-128.
- **نیاز به دو خوانش یکسان** برای فرمت‌های بدون رقم کنترلی الزامی: CODE-39، ITF.

`minLineCount` روی ۱ است تا فریم کمی تار میان‌رده رد نشود؛ دقت فرمت‌های بدون
رقم کنترلی همان تأیید دوم است.

## ۳. فرمت‌های پشتیبانی‌شده

| فرمت                | از کجا می‌آید                                            |
| ------------------- | -------------------------------------------------------- |
| CODE-128            | کدِ تولیدی خودِ اپ (`generateUniqueCode` → `PABC234XYZ`) |
| EAN-13              | کالای خرده‌فروشی + چاپ لیبل اپ (`barcode.ts`)            |
| EAN-8، UPC-A، UPC-E | کالای خرده‌فروشی                                         |
| CODE-39، ITF        | بارکدهای انبارگردانی/بسته‌بندی                           |
| QR، DataMatrix      | کد محصول/لیبل داخلی                                      |

**توجه:** zxing برای UPC-A مقدار ۱۳رقمی با صفر پیشوند برمی‌گرداند
(`012345678905` → `0012345678905`) و UPC-E را به شکل EAN-13 بسط می‌دهد. تطبیق با
کد ذخیره‌شده در `src/lib/barcode-match.ts` انجام می‌شود که همین حالت را از قبل
پوشش می‌دهد. آن فایل با `store.ts` مشترک است و **تغییر نکرده**.

## ۴. ساختار فایل‌ها

```
src/features/scanner/
  index.ts          خروجی عمومی
  Scanner.tsx       فقط UI (کادر، دکمه‌ها، خطا)
  useScanner.ts     پل React ↔ ScannerSession
  session.ts        حلقهٔ فریم، Native+ZXing، dispose واحد
  camera.ts         باز/بست استریم، torch، zoom، focus
  camera-select.ts  امتیازدهی لنز + زوم شروع (خالص، تست‌شده)
  frame-source.ts   کراپ فریم با تشخیص فریم سیاه
  geometry.ts       هندسهٔ کادر و نگاشت object-fit:cover
  native.ts         BarcodeDetector بومی، غیرمسدودکننده
  pixels.ts         واریانس RGBA / فریم مرده
  accept.ts         دروازهٔ پذیرش/دوباره‌خوانی
  formats.ts        فهرست فرمت‌ها + نگاشت نام بومی
  decoder/
    index.ts        نمای Decoder (Worker با پشتیبان ترد اصلی)
    decode.worker.ts
    zxing.ts        صدا زدن readBarcodes (مشترک Worker و ترد اصلی)
```

`src/components/Scanner.tsx` فقط re-export است تا `src/routes/scan.tsx`
دست‌نخورده بماند. قرارداد عمومی بدون تغییر:

```tsx
<Scanner onDetected={(code: string, format?: string) => void} paused={boolean} />
```

## ۵. امنیت منابع

کل چرخهٔ عمر در یک `ScannerSession` است و یک `dispose()` دارد که:
تراک‌های دوربین را stop می‌کند، Worker را terminate می‌کند، Native را خاموش
می‌کند، `cancelVideoFrameCallback` را صدا می‌زند، `AudioContext` را می‌بندد و هر
`ImageBitmap` باز را `close()` می‌کند. افکت React فقط می‌سازد و dispose می‌کند.

اسکنر **هیچ عارضهٔ جانبی ندارد**: نه دیتابیس، نه localStorage، نه رکورد کاربر.
تنها خروجی‌اش صدا زدن `onDetected` با یک رشته است.

## ۶. تست

```bash
npx --yes tsx --tsconfig tsconfig.json scripts/test-scanner.ts
```

تست بارکد واقعی می‌سازد (`bwip-js` + `qrcode`، هر دو از قبل در پروژه هستند)،
آن را به پیکسل خام RGBA تبدیل می‌کند و با همان موتور پروداکشن می‌خواند —
رفت‌وبرگشت کامل برای هر فرمت، به‌علاوهٔ فریم نویز و فریم سفید برای اثبات
نبودِ خوانش اشتباه.
