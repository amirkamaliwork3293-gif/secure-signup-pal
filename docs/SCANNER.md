# اسکنر بارکد/QR — معماری بازنویسی‌شده

این سند جایگزین تاریخِ کامنت‌های «v1…v7» در فایل قدیمی `src/components/Scanner.tsx` است.
پیاده‌سازی قبلی هفت دور وصله روی وصله خورده بود و روی بعضی گوشی‌های اندروید
بی‌صدا کار نمی‌کرد. این نسخه از صفر نوشته شده است.

## ۱. چرا نسخهٔ قبلی روی بعضی گوشی‌ها کار نمی‌کرد

سه علت ریشه‌ای که در بازنویسی هدف گرفته شدند:

1. **دو موتور دیکود موازی.** نسخهٔ قبل `BarcodeDetector` بومی و ZXing را هم‌زمان
   مسابقه می‌داد. اما `BarcodeDetector` در **WebView اندروید وجود ندارد** و اپ
   کامیکس یک پوستهٔ Capacitor است که `https://kamixapp.ir` را در همان WebView باز
   می‌کند (`.github/workflows/build-apk.yml`). یعنی کاربر مرورگر کروم و کاربر اپ
   دو موتور مختلف را اجرا می‌کردند و رفتار هرگز یکسان نبود.
2. **انتخاب اشتباه لنز.** `facingMode: "environment"` روی گوشی‌های چنددوربینه
   (سامسونگ، شیائومی) معمولاً به لنز **ultra-wide / macro / depth** بسته می‌شود که
   در فاصلهٔ بارکد فوکوس نمی‌کند. پیش‌نمایش سالم دیده می‌شود ولی هیچ‌وقت چیزی
   خوانده نمی‌شود — همان «روی گوشی من کار می‌کند، روی گوشی برادرم نه».
   انتخاب قبلی («آخرین videoinput») یک حدس بود.
3. **watchdog و بازیافت Worker در حلقهٔ فریم.** تایم‌اوت‌های ۳۲۰ms/۱s و شمارندهٔ
   hang، رفتار را غیرقطعی می‌کرد: یک detect کند، موتور را برای همیشه خاموش می‌کرد.

## ۲. تصمیم‌های معماری

### یک موتور دیکود، نه دو تا

`zxing-wasm` (همان zxing-cpp کامپایل‌شده به WebAssembly) تنها موتور است و در یک
Worker اجرا می‌شود. `BarcodeDetector` بومی **عمداً حذف شده** — قطعی‌بودن رفتار روی
کل بازار اندروید از چند میلی‌ثانیه سرعت بیشتر ML Kit ارزشمندتر است.

اندازه‌گیری روی همین مخزن (Node، پیکسل خام، بعد از گرم شدن ماژول):

| فرمت     | زمان دیکود |
| -------- | ---------- |
| EAN-13   | ~۰.۷ms     |
| EAN-8    | ~۰.۷ms     |
| CODE-128 | ~۳.۳ms     |
| ITF      | ~۱.۵ms     |
| CODE-39  | ~۶.۷ms     |
| QR       | <۱ms       |

با این بودجه، مسابقه دادن دو موتور هیچ سودی ندارد.

### زنجیرهٔ تنزل (graceful degradation)

یک بار در شروع، نه در هر فریم:

```
Worker ماژول + OffscreenCanvas      ← کروم/WebView جدید
  ↓ handshake در ۳ ثانیه جواب نداد
دیکود zxing-wasm روی ترد اصلی        ← WebView قدیمی بدون module worker
```

گرفتن فریم هم مستقل تنزل می‌کند:

```
createImageBitmap(video, crop) → transfer به Worker   ← مسیر سریع
  ↓ پشتیبانی نمی‌شود
canvas + getImageData → transfer بافر RGBA            ← مسیر سازگار
```

هیچ‌کدام از این تصمیم‌ها در حلقهٔ فریم دوباره ارزیابی نمی‌شود.

### انتخاب لنز عقب + تأیید زنده‌بودن

1. یک استریم کمینه برای گرفتن مجوز (قبل از مجوز، `enumerateDevices` لیبل نمی‌دهد).
2. `enumerateDevices()` و امتیازدهی به دوربین‌های عقب: لیبل‌های
   `ultra / wide / tele / depth / mono / macro` **تنزل رتبه** می‌گیرند.
3. باز کردن دوباره با `deviceId: { exact }` + `focusMode: continuous`.
4. **تأیید می‌کنیم که فریم واقعاً می‌آید**؛ اگر نیامد، خودکار به کاندیدای بعدی
   می‌رویم. این همان حالتی است که قبلاً بی‌صدا شکست می‌خورد.
5. دکمهٔ تغییر لنز برای کاربر باقی می‌ماند (راه فرار انسانی).

انتخاب لنز **ذخیره نمی‌شود**؛ محدودیت پروژه نوشتن در localStorage را منع می‌کند.

### فشار معکوس (backpressure)

حلقه با `requestVideoFrameCallback` (یا rAF) اجرا می‌شود و **هم‌زمان فقط یک دیکود**
در پرواز است. فریم جدید در صف نمی‌رود، دور ریخته می‌شود. نتیجه: پیش‌نمایش هرگز
لگ نمی‌گیرد، چون هیچ صفی رشد نمی‌کند.

`tryHarder` / `tryRotate` / `tryInvert` / `tryDownscale` خودِ zxing-cpp، جای هکِ
«کراپ زوم‌شدهٔ فریم‌های فرد/زوج» و پاس دستی invert نسخهٔ قبل را گرفته‌اند.

### دروازهٔ دقت

`validateOptionalChecksum` روی `false` است (روشن بودنش CODE-39 بدون رقم کنترلی
اختیاری را رد می‌کرد). به جایش:

- **پذیرش فوری** برای فرمت‌هایی که خودشان کنترل می‌شوند: QR، DataMatrix،
  EAN-8/13، UPC-A/E، CODE-128.
- **نیاز به دو خوانش یکسان** برای فرمت‌های بدون رقم کنترلی الزامی: CODE-39، ITF.

همچنین `minLineCount: 2` خودِ zxing یعنی هر بارکد خطی باید در دو خط اسکن یکسان
خوانده شود.

## ۳. فرمت‌های پشتیبانی‌شده

| فرمت                | از کجا می‌آید                                            |
| ------------------- | -------------------------------------------------------- |
| CODE-128            | کدِ تولیدی خودِ اپ (`generateUniqueCode` → `PABC234XYZ`) |
| EAN-13              | کالای خرده‌فروشی + چاپ لیبل اپ (`barcode.ts`)            |
| EAN-8، UPC-A، UPC-E | کالای خرده‌فروشی                                         |
| CODE-39، ITF        | بارکدهای انبارگردانی/بسته‌بندی                           |
| QR، DataMatrix      | کد محصول/لیبل داخلی                                      |

**توجه:** zxing برای UPC-A مقدار ۱۳رقمی با صفر پیشوند برمی‌گرداند
(`012345678905` → `0012345678905`) و UPC-E را به شکل EAN-13 بسط می‌دهد. تطبیق با
کد ذخیره‌شده در `src/lib/barcode-match.ts` انجام می‌شود که همین حالت را از قبل
پوشش می‌دهد. آن فایل با `store.ts` مشترک است و **تغییر نکرده**.

## ۴. ساختار فایل‌ها

```
src/features/scanner/
  index.ts          خروجی عمومی
  Scanner.tsx       فقط UI (کادر، دکمه‌ها، خطا)
  useScanner.ts     پل React ↔ ScannerSession
  session.ts        حلقهٔ فریم، backpressure، dispose واحد
  camera.ts         باز/بست استریم، torch، zoom، focus
  camera-select.ts  امتیازدهی لنز (خالص، تست‌شده)
  frame-source.ts   کراپ فریم با تنزل قابلیت
  geometry.ts       هندسهٔ کادر (خالص، تست‌شده)
  accept.ts         دروازهٔ پذیرش/دوباره‌خوانی (خالص، تست‌شده)
  formats.ts        تنها منبع فهرست فرمت‌ها
  decoder/
    index.ts        نمای Decoder (Worker با پشتیبان ترد اصلی)
    decode.worker.ts
    zxing.ts        صدا زدن readBarcodes (مشترک Worker و ترد اصلی)
```

`src/components/Scanner.tsx` فقط re-export است تا `src/routes/scan.tsx`
دست‌نخورده بماند. قرارداد عمومی بدون تغییر:

```tsx
<Scanner onDetected={(code: string, format?: string) => void} paused={boolean} />
```

## ۵. امنیت منابع

کل چرخهٔ عمر در یک `ScannerSession` است و یک `dispose()` دارد که:
تراک‌های دوربین را stop می‌کند، Worker را terminate می‌کند،
`cancelVideoFrameCallback` را صدا می‌زند، `AudioContext` را می‌بندد و هر
`ImageBitmap` باز را `close()` می‌کند. افکت React فقط می‌سازد و dispose می‌کند.

اسکنر **هیچ عارضهٔ جانبی ندارد**: نه دیتابیس، نه localStorage، نه رکورد کاربر.
تنها خروجی‌اش صدا زدن `onDetected` با یک رشته است.

## ۶. تست

```bash
npx --yes tsx --tsconfig tsconfig.json scripts/test-scanner.ts
```

تست بارکد واقعی می‌سازد (`bwip-js` + `qrcode`، هر دو از قبل در پروژه هستند)،
آن را به پیکسل خام RGBA تبدیل می‌کند و با همان موتور پروداکشن می‌خواند —
رفت‌وبرگشت کامل برای هر فرمت، به‌علاوهٔ فریم نویز و فریم سفید برای اثبات
نبودِ خوانش اشتباه.
